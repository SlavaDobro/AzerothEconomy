# AzerothEconomy 1.0.0

[Скачать JAR 1.0.0](https://github.com/SlavaDobro/AzerothEconomy/raw/refs/heads/main/dist/AzerothEconomy-1.0.0.jar) · [Архив исходников](https://github.com/SlavaDobro/AzerothEconomy/raw/refs/heads/main/dist/AzerothEconomy-1.0.0-sources.zip) · [Отчёт тестов](docs/TESTS.md)

Самостоятельный плагин экономики для установленного Paper 26.3 build 244. Интерфейс на русском. Основной баланс — **целое число медных монет**, владелец — UUID аккаунта. 100 медных = 1 серебряная, 100 серебряных = 1 золотая. UltraEconomy использован только как ориентир функций; его код, оформление и ресурсы не использованы.

## Что работает

- Кошелёк, дополнительные валюты, офлайн-переводы, точный обмен, история, административные give/take/set; ограничения, права и комиссии.
- Vault legacy Economy в VaultUnlocked 2.20.3: **1 Vault unit = 1 медная**, дробные суммы запрещены. Один общий баланс; отдельной копии для Vault нет.
- Предметный банк: вкладки, покупка вкладок и ячеек, названия, иконки, журнал, доступ через команду и NPC/API.
- Почта с темой, текстом, предметами, деньгами, задержкой, сроком, ответом, возвратом, отдельным получением и «Забрать всё». COD оплачивает всю посылку один раз; выручка отправляется отправителю отдельным письмом.
- GUI торговли: запрос, принятие, отмена, расстояние, тайм-аут, предметы и несколько валют, подтверждение версии предложения, обратный отсчёт. Предметы результата идут в почту; возвраты — в получение, деньги возврата — в почту.
- Аукцион фиксированных цен: залог, комиссия, поиск по материалу/названию, свои лоты, страницы, отмена, истечение срока, единственный покупатель. Доставка и выручка — почтой.
- Отключаемые чеки с серверными ID, денежный счёт банка, обычный XP, общий предметный/денежный банк с ролями, проценты, выплаты по расписанию, награды за типы мобов и потери при смерти. **Все дополнительные источники денег и штрафы выключены.**
- SQLite и отдельный MariaDB SQL backend; миграции схемы 1→2→3; резервные копии, диагностика, журнал предметов и денег, обнаружение незавершённых переносов.
- PlaceholderAPI, публичный сервис EconomyApi, события после commit, русские GUI/сообщения, Nexo-иконки с текстовым fallback, кнопка в существующем CommandPanels `/menu`.

## Файлы и сборка

В репозитории находится **полный исходный код плагина**, включая тесты, русские конфигурации, Maven Wrapper и документацию. Для обычной сборки **не нужны папка сервера, платные плагины или файлы с компьютера автора**. Нужны JDK 25+ и доступ к интернету для загрузки открытых API и Maven-зависимостей.

Скачать всё: **Code → Download ZIP** или:

```sh
git clone https://github.com/SlavaDobro/AzerothEconomy.git
cd AzerothEconomy
```

Windows PowerShell:

```powershell
# JAVA_HOME должен указывать на установленный JDK 25 или 26.
./build.ps1
```

Linux/macOS:

```sh
chmod +x mvnw build.sh
./build.sh
```

Результат: `target/AzerothEconomy-1.0.0.jar`. Уже собранный и проверенный на сервере JAR находится в `dist/`, готовые конфиги — в `dist/config/`.

Maven Wrapper 3.3.2 загружает Maven 3.9.9 с проверкой SHA-256. Paper API закреплён на `26.3.build.244-stable`; Vault API загружается из публичного Maven-репозитория. PlaceholderAPI 2.12.3 загружается скриптом из официального GitHub Release с проверкой SHA-256 (его Maven-репозиторий при публикации отвечал HTTP 403). После первого запуска скрипта можно использовать `./mvnw.cmd clean verify` или `./mvnw clean verify` напрямую. Подробности: [переносимая сборка](docs/PORTABLE-BUILD.md).

Для точного повторения первоначальной сборки против установленного набора серверных JAR сохранены `pom-server.xml`, `build-server.ps1` и `deps/manifest.json` с 54 SHA-256. Этот дополнительный режим требует соответствующего `../server`; обычная сборка `build.ps1`/`build.sh` от него не зависит. Платные зависимости не включены в репозиторий.

Проверки MariaDB опциональны: `./build.ps1 -MariaDbTests` либо `./build.sh -Dae.mariadb.tests=true`. Нужен отдельный MariaDB на `127.0.0.1:33077`; тесты создают и удаляют только временные схемы `ae_test_*`. Не направляйте их на рабочую БД.

## Установка

1. Остановить сервер штатной командой `stop`, убедиться, что процесс завершён.
2. Скопировать резервную копию **всей** папки сервера, особенно world/playerdata, плагины, конфиги и БД. Не заменять JAR в работающей сборке.
3. Скопировать JAR в `server/plugins`. Конфиги появятся в `server/plugins/AzerothEconomy`: `config.yml`, `messages.yml`, `ui.yml`.
4. CMI `Economy.Enabled` оставить `false`. Другие провайдеры экономики не включать. `/money`, `/balance`, `/pay`, `/bank`, `/mail` плагин по умолчанию не регистрирует. Использовать `/aeconomy`.
5. Запустить `server/start.bat`. Проверить консоль: AzerothEconomy включён, `aeconomy diagnose` сообщает integrity=ok и единственного провайдера AzerothEconomy.

Порядок загрузки: после Vault/PlaceholderAPI, до MMOCore/MMOItems/CMI. Если другой Economy уже зарегистрирован, запуск прекращается. Если второй провайдер появляется позже, собственные пользовательские операции блокируются. После исправления нужен полный перезапуск; `/reload` не поддерживается.

Старые балансы **не импортируются**. При обследовании CMI Economy была выключена, в последнем журнале провайдер отсутствовал, одна запись CMI имела Balance=0; исходная БД оставлена без изменений. Источник и коэффициент для будущего импорта необходимо определить явно. Не меняйте online-mode/UUID-политику сервера после появления балансов.

Порядок безопасной установки описан в [INSTALLATION.md](docs/INSTALLATION.md). Локальные серверные данные и резервные копии в репозиторий не включены.

## Быстрая проверка в игре

- Открыть `/aeconomy`, затем `/menu` → «Экономика».
- В консоли: `aeconomy give <ник> gold 2g 34s 56c`. В кошельке должно быть `2 з 34 с 56 м`; `%aeconomy_raw_gold%` — `23456`.
- Взять предмет MMOItems/Nexo в руку, открыть банк, внести и получить его; сверить характеристики, количество, привязку, прочность и способности.
- Два тестовых игрока: `/aeconomy pay <ник> gold 1g`; подтвердить и сверить оба баланса.
- Почта: `/aeconomy deposit` → скопировать ID из чата → `/aeconomy mail attach <ID>` → `/aeconomy mail send <ник> gold 0 1g Тест|Посылка с оплатой`. Нужен второй игрок с 1g. Проверить оплату один раз и письмо с выручкой.
- `/aeconomy trade <ник>`, второй игрок — `trade accept`; добавить предметы и валюты, подтвердить оба предложения. Изменение суммы должно снять подписи. Проверить выход, смерть, отход дальше 8 блоков и переполненный инвентарь.
- `/aeconomy auction sell 1g`; другой игрок покупает через GUI; проверить письма и удержание комиссии.

Используйте отдельный тестовый сервер/аккаунты. Автоматические испытания не заменяют эту совместную проверку двумя настоящими клиентами.

## Настройки и правила

`config.yml` содержит валюты, модули, комиссии, лимиты, расписания и права доступа к валютам. Все суммы конфигурации — минимальные единицы; для дополнительной валюты минимальная единица определяется `precision`: например precision=2 означает 0.01. Не меняйте точность существующего ID: плагин отклонит такую конфигурацию. Не удаляйте валюту с ненулевыми остатками. Перезагрузка конфигурации — штатным перезапуском сервера.

Обычное число для gold — медные: `12345`. Номиналы: `1g 23s 45c` либо `1з 23с 45м`; обозначения задаются `units`. Для `mail send` суммы занимают по одному аргументу: `1g23s45c`. Десятичные суммы разрешены только дополнительным валютам в пределах precision. Отрицательные суммы, exponent notation, NaN, Infinity и переполнение отклоняются.

Курс обмена — дробь `numerator/denominator` выходных минимальных единиц за входную. Комиссия задаётся базисными пунктами: 100 = 1%. Выход округляется вниз, комиссии перевода/аукциона — вверх. Прибыльные циклы любой длины отклоняются точной рациональной проверкой. Обмен чести, арены и жетонов по умолчанию отсутствует.

Банк стартует с одной вкладки на 9 стопок; расширяется блоками по 9, до 45 на вкладку. При полном инвентаре выдача требует свободной ячейки и сохраняет остаток в хранилище; предметы не выбрасываются. Шалкеры и bundles не принимаются, чтобы не обходить ограничения вложенными привязанными предметами.

`bank.remote` и `mail.remote` выключают удалённый доступ; NPC вызывает API либо консоль `aeconomy npc bank|mail <ник>`. Такой вызов даёт 60 секунд доступа. Администраторы имеют отдельные `.remote` права. Общий `/aeconomy inbox` предназначен для почтовых/торговых доставок; прямое получение предмета из банковской вкладки повторно проверяет банковский доступ.

Чек подтверждается UUID в PDC **и записью vouchers**. Копии одного чека можно предъявить, но погашение проходит только один раз. Погашенный бумажный предмет может остаться в инвентаре и больше не имеет денежной ценности; имя/lore не являются подтверждением.

Проценты начисляются на денежные банковские счета. Выплаты и проценты имеют постоянный ID периода; перезапуск в том же периоде не создаёт повтор. Пропущенные периоды при выключенном сервере не догоняются. Периоды считаются от Unix epoch; дневные лимиты общего банка — сутки UTC (03:00 по Москве). Создание денег через `MINT`, проценты и mob-rewards включаются только администратором явно.

Общий банк имеет собственные роли OWNER/OFFICER/MEMBER и не синхронизирует членство гильдий MMOCore. MEMBER вносит, OFFICER снимает в пределах дневных лимитов, OWNER управляет ролями и снимает без дневного ограничения. Для предметного общего банка предмет сначала вносится в личное получение, затем `guild store`.

Обычный XP хранится отдельно от валют и данных MMOCore. При включённом `override-vanilla-exp` или `vanilla-exp-redirection.enabled` команды переноса XP запрещены. На этой сборке override включён, поэтому модуль XP оставлен выключенным.
