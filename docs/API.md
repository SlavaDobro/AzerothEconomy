# API

Получить сервис после включения плагинов:

```java
EconomyApi api = Bukkit.getServicesManager().load(EconomyApi.class);
long copper = api.balance(playerUuid, "gold"); // неизменяемый cache, без SQL
UUID operation = UUID.randomUUID(); // сохранить у себя до вызова
api.transfer(operation, fromUuid, toUuid, "gold", 12345L)
   .whenComplete((unused, error) -> { /* успех только после commit */ });
api.reward(rewardId, recipient, "Награда", "За прохождение", "gold", 10000L);
// Только на потоке Paper; ItemStack копируются/сериализуются до фоновой работы:
api.rewardItems(rewardId, recipient, "Предметы", List.of(item));
// Только из доверенного NPC-взаимодействия, на основном потоке:
api.openBank(player);
api.openMail(player);
```

Используйте `depend: [TerraWoWmain]` в plugin.yml своего расширения. Для компиляции подключите JAR плагина как compileOnly/provided, не включайте его классы в свой JAR.

Денежные единицы API — long минимальных единиц выбранной валюты. `reward` явно создаёт деньги; `rewardItems` явно создаёт предметы. Вызывающий плагин отвечает за право выдать награду и за стабильность ID. Повтор того же ID с теми же параметрами не выдаёт награду снова; конфликт параметров отклоняется. Для каждой логической награды/перевода храните отдельный постоянный UUID. Не вызывайте `join()`/`get()` будущего результата с игрового потока.

`EconomyCommittedEvent` — уведомление об успешной API-операции, поля `operation()` и `kind()`. `LedgerCommittedEvent` публикуется после каждой денежной транзакции, в том числе через команды/Vault; `changes()` содержит operation, owner, currency, delta, balance, reason. Оба события идут на главном потоке, не отменяемы и не являются предварительным согласованием. Подписчик не должен повторять исходную операцию при обработке уведомления.

Для предметов используется Paper `ItemStack.serializeAsBytes()/deserializeBytes()`. API получает Bukkit-объекты только на главном потоке; в рабочую очередь идут byte[], UUID, строки и числа. Нельзя вызывать методы Ledger напрямую с произвольного потока или изменять его внутреннюю БД сторонними плагинами: внешний контракт — EconomyApi.

## PlaceholderAPI

- `%twm_gold%` — `1 з 23 с 45 м`.
- `%twm_raw_gold%` — `12345`.
- `%twm_honor%`, `%twm_arena%`, `%twm_dungeon%` — форматированные значения.
- `%twm_raw_<id>%` — целое число минимальных единиц любой конфигурируемой валюты.

Значения берутся из кэша последнего подтверждённого commit. Неизвестный плейсхолдер возвращает null для стандартного поведения PAPI.

## Vault

Регистрируется `net.milkbowl.vault.economy.Economy`, который поддерживает установленный VaultUnlocked. Единица — 1 медная, fractionalDigits=0. Все варианты world используют один баланс UUID. NaN, Infinity, отрицательные и дробные double отклоняются; внутренние расчёты используют long/BigInteger/BigDecimal. Предел gold не превышает 2^53−1, чтобы преобразование в double не теряло целые единицы.

Именованные shared banks legacy Vault не реализуются (`hasBankSupport=false` и NOT_IMPLEMENTED), поскольку собственные банки имеют другой API/модель доступа. Нативный `net.milkbowl.vault2.economy.Economy` отдельно не регистрируется. Совместимость проверена с legacy-клиентами установленной сборки.

Синхронный Vault требует результата до возврата метода. Для SQLite выполняются короткие индексированные durable транзакции с немедленным отказом при занятом mutex и busy_timeout 25ms; операции GUI, поиск, backup, диагностика и фоновые задания выполняются вне игрового потока. Медленная локальная файловая система всё ещё может задержать fsync: это явная граница legacy-контракта.

Для сетевого MariaDB backend запись legacy Vault **отклоняется на игровом потоке**; используйте асинхронный EconomyApi или вызов Vault вне игрового потока со стороны совместимого клиента. Не переключайте рабочую сборку на MariaDB, рассчитывая на прозрачность синхронных legacy-магазинов. SQLite — проверенный основной режим этой установки.
