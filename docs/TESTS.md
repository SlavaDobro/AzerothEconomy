# Отчёт испытаний и ограничения

Экономика проверялась 9 ноября 2026 года в отдельных временных БД и на изолированном тестовом сервере (`test-server`, готовится `tools/prepare-test-server.py`). Рабочие UUID и балансы не использовались. Paper слушал только `127.0.0.1:25576`, MariaDB — `127.0.0.1:33077`. Тестовый мир и данные плагинов были изолированы, playerdata и база CMI исходного сервера в тест не копировались. Маунты, питомцы и расы 11–12 ноября проверены в игре на рабочем сервере.

Тест сохранности soulbound через четыре доменных маршрута специально работает на внутренних синтетических записях и проверяет **сохранение метаданных**, а не разрешает такую передачу пользователю. Отдельный runtime-тест проверяет, что публичный путь передачи soulbound отвергается. При первом runtime-прогоне был обнаружен ленивый loader MMOItems; после исправления тест прошёл.

## Границы проверки и отсутствующие функции

- Не выполнялась ручная сессия двух реальных клиентов, визуальная проверка каждого экрана в Minecraft, сетевое переподключение во время countdown, фактическая смерть участника или физическое отключение диска во время player.saveData. Данные GUI handlers и JVM crash-тест не выдаются за эти проверки.
- Не выполнен нагрузочный soak-тест с сотнями игроков и гигабайтами истории, проверка поведения OneDrive/антивируса при fsync, fuzzing всех NBT-вариантов и аудит всех сторонних плагинов. Нет утверждения «защита от всех дюпов».
- Неоднозначные inventory↔DB переходы требуют ручного восстановления; автоматическая догадка о фактическом месте предмета намеренно отсутствует. Полный rollback мира отдельно от БД не поддерживается.
- Bundle и Shulker Box отвергаются целиком. Внешние custom-backpack системы не заявлены как совместимые. Слоты расширенного MMOInventory не обслуживаются — используется стандартный PlayerInventory.
- Роли общего банка собственные; интеграция членства гильдий MMOCore не реализована. Баланс/банк принадлежат UUID аккаунта, а не переключаемому профилю персонажа.
- Банк обычного XP реализован, но на данной конфигурации MMOCore использовать его нельзя без отдельно согласованной настройки XP. Класс/профессии не изменяются.
- Отдельный native Vault2 multi-currency provider не реализован; используется legacy Economy через VaultUnlocked. Сетевой MariaDB backend не выполняет синхронные Vault-записи с игрового потока. Рабочая установка использует SQLite.
- Реальный Oracle MySQL server не запускался. MariaDB SQL implementation проверена на MariaDB 11.4.5; не объявляется универсальная совместимость со всеми MySQL/MariaDB версиями.
- Автоматического конвертера SQLite↔MariaDB и импорта чужих балансов нет. Есть проверенное восстановление backup в тот же backend и миграции собственной схемы.
- Аукцион — фиксированная цена, без ставок. Неработающих кнопок ставок нет. Текст и суммы вводятся командами; графического текстового редактора писем нет.
- Награды за конкретные внутренние MythicMobs ID подключаются внешним сценарием через API/консоль; встроенный автоматический модуль работает с Bukkit EntityType.
- Folia, несколько серверов с общей БД, сторонние ресурспаки и будущие версии API не проверены. Система квестов не создавалась.

## Повторение

Из папки проекта `./build.ps1` или `./build.sh` загружает открытые API и запускает SQLite/JVM-тесты. `build-server.ps1` дополнительно проверяет SHA точных локальных серверных зависимостей для первоначальной сборки. `./build.ps1 -MariaDbTests` добавляет тесты на отдельном MariaDB loopback:33077. См. исходники `src/test/java` и tools/run-runtime.py. Последний работает только с подготовленной изолированной папкой; testing.self-test и testing.stop-after-tests на основном сервере false.
